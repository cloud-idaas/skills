# Go 构建与验证

先识别目标文件最近的 `go.mod`、活动 `go.work` 和 CI 入口，读取 `go` / `toolchain` 声明。Go 1.22 是基础门槛；项目或 SDK 依赖要求更高时以实际声明为准。

- 单模块：在该 `go.mod` 所在目录添加依赖，运行 `go mod tidy`、`go build ./...`、`go vet ./...`、`go test ./...`。
- 多模块：列出改动涉及的模块及本地依赖模块；逐模块添加/整理所需依赖，并分别执行上述验证。仓库根没有 `go.mod` 时，不在根目录机械运行 `go build ./...`。
- workspace：用 `go env GOWORK` 确认活动文件，用 `go work edit -json` 读取 `Use`。逐个进入相关 `use` 模块执行 build/vet/test；workspace 根的 `./...` 不能替代模块验证。不创建、覆盖或提交开发者原有 go.work。
- 使用项目 CI 已有的 tags、生成步骤、Makefile 入口和工具链；生成代码失败时记录具体前置条件，不删除或跳过业务模块。
- 本地阶段不要求部署 Secret；项目若将云端集成测试单列，使用既有本地测试入口，并报告未执行的集成测试。
- 记录每个模块的路径、实际命令、结果与跳过项；依赖解析需网络与业务云端冒烟分别报告。
